
Практическая задача №2: Настройка автоматического монтирования с оптимизацией
Описание задачи
Эта задача моделирует реальную ситуацию настройки постоянного хранилища для базы данных с учётом производительности и надёжности. Вы настроите автоматическое монтирование через fstab со специальными опциями.

Что нужно сделать:
Этап 1: Подготовка второго виртуального диска

Создайте новый файл-образ размером 300MB для этой задачи:

dd if=/dev/zero of=~/database_disk.img bs=1M count=300
sudo losetup -f ~/database_disk.img --show

                  
Этап 2: Создание одного раздела на весь диск

Используйте parted в командном режиме для быстрого создания раздела:

sudo parted /dev/loop1 mklabel gpt
sudo parted /dev/loop1 mkpart primary ext4 0% 100%

                  
Здесь /dev/loop1 - замените на реальное имя вашего loop-устройства.

Этап 3: Создание оптимизированной файловой системы

Создайте ext4 с особыми параметрами для базы данных. Дополнительная информация: флаг -E позволяет указать расширенные опции, а stride и stripe-width оптимизируют работу с блоками:

sudo mkfs.ext4 -L "DATABASE" -E stride=32,stripe-width=64 /dev/loop1p1

                  
Этап 4: Получение UUID и настройка fstab

Сначала узнайте UUID созданной файловой системы и запишите его. Затем создайте точку монтирования:

sudo mkdir -p /mnt/database

                  
Теперь добавьте запись в /etc/fstab. Используйте редактор с правами root и добавьте строку с такими опциями:

Монтирование по UUID
Опция noatime для производительности
Опция nodiratime для дополнительной оптимизации
Опция data=writeback для ускорения записи (подходит для баз данных с собственным журналированием)
Опция barrier=0 для отключения барьеров записи (использовать только если есть ИБП)
Параметры dump=0 и pass=2
Формат строки должен быть примерно таким:

UUID=ваш-uuid-здесь /mnt/database ext4 noatime,nodiratime,data=writeback,barrier=0 0 2

                  
Важное замечание: опции data=writeback и barrier=0 могут привести к потере данных при сбое питания. В реальной системе используйте их только с ИБП и для баз данных с собственными механизмами обеспечения целостности.

Этап 5: Тестирование автоматического монтирования

Проверьте правильность настройки без перезагрузки:

sudo mount -a

                  
Если ошибок нет, создайте тестовую структуру каталогов, имитирующую базу данных:

sudo mkdir -p /mnt/database/{data,logs,backup}
sudo touch /mnt/database/data/table1.db
sudo touch /mnt/database/logs/transaction.log

                  
Что предоставить в качестве ответа:
Сделайте скриншот, на котором последовательно выполнены и видны результаты команд:

grep database /etc/fstab
mount | grep database
ls -la /mnt/database/
df -h /mnt/database

                  
На скриншоте должны быть чётко видны: строка из fstab с правильными опциями монтирования, информация о примонтированной файловой системе с указанными опциями, структура созданных директорий и информация о размере и использовании раздела.

Важное примечание по безопасности:
После выполнения задачи обязательно удалите добавленную строку из /etc/fstab, чтобы система не пыталась монтировать несуществующее устройство при следующей загрузке. Также отключите loop-устройство и удалите файл-образ.
